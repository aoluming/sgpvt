# 训练时间统计与分析

本文档说明如何使用训练时间统计功能来对比两个训练方法的计算开销。

## 功能说明

已为两个训练器添加了时间统计功能：
- `llava_trainer_gakl.py` - GAKL方法（简化版本）
- `llava_trainer_copy.py` - COPY方法（带注意力分析和扰动）

## 统计指标

训练过程中会自动记录以下指标：

1. **每步训练时间**：每个训练步骤的耗时（秒）
2. **总训练时间**：所有训练步骤的累计时间（秒）
3. **总耗时**：从训练开始到结束的总时间（包含所有开销）
4. **平均每步时间**：所有步骤的平均耗时
5. **最快/最慢步骤时间**：性能边界值

## 使用方法

### 1. 运行训练

正常运行训练脚本，时间统计会自动进行：

```bash
# 运行GAKL方法
bash scripts/v1_5/finetune_lora_gakl.sh

# 运行COPY方法
bash scripts/v1_5/finetune_lora_copy.sh
```

### 2. 查看实时统计

训练过程中，每10步会输出一次时间统计：

```
[时间统计] Step 10: 当前步骤耗时=2.3456秒, 最近10步平均耗时=2.1234秒, 累计训练时间=21.23秒 (0.35分钟)
```

### 3. 查看最终统计

训练结束后，会自动输出完整的统计摘要：

```
================================================================================
训练时间统计摘要 (GAKL方法)
================================================================================
总训练步数: 100
总训练时间: 212.34秒 (3.54分钟, 0.06小时)
从开始到结束的耗时: 215.67秒 (3.59分钟, 0.06小时)
平均每步耗时: 2.1234秒
最快步骤耗时: 1.9876秒
最慢步骤耗时: 2.4567秒
每步耗时标准差: 0.1234秒
================================================================================
时间统计信息已保存到: /path/to/output/training_time_stats.json
```

### 4. 对比两个方法

使用对比脚本分析两个方法的性能差异：

```bash
python scripts/compare_training_time.py \
    /data1/zzj/llava_output_zzj_new/output_ga_joebiden/training_time_stats.json \
    /data1/zzj/llava_output_zzj_new/output_sgpvt_joebiden/training_time_stats.json
```

对比脚本会输出详细的对比分析，包括：
- 总训练时间对比
- 每步平均时间对比
- 最值对比
- 计算开销分析
- 总结报告

## 输出文件

训练结束后，会在输出目录生成 `training_time_stats.json` 文件，包含：

```json
{
  "method": "GAKL",
  "total_steps": 100,
  "total_training_time_seconds": 212.34,
  "elapsed_time_seconds": 215.67,
  "avg_step_time_seconds": 2.1234,
  "min_step_time_seconds": 1.9876,
  "max_step_time_seconds": 2.4567,
  "step_times": [2.1, 2.2, 2.0, ...]  // 前100步的详细时间
}
```

## 注意事项

1. **多GPU训练**：时间统计只在主进程（rank 0）输出，避免重复打印
2. **文件保存**：统计文件只在主进程保存
3. **内存使用**：只保存前100步的详细时间，避免文件过大
4. **精度**：时间统计使用 `time.time()`，精度为秒级

## 性能分析建议

1. **对比实验**：确保两个方法使用相同的：
   - 数据集
   - 批次大小
   - 训练步数
   - 硬件配置

2. **多次运行**：建议多次运行取平均值，减少随机波动影响

3. **详细分析**：查看 `step_times` 数组，分析时间分布和波动情况

4. **开销分解**：通过对比 `total_training_time_seconds` 和 `elapsed_time_seconds`，了解额外开销（如数据加载、模型保存等）
